# 个人成长统计功能设计文档

**日期：** 2026-05-22  
**目标用户：** 普通球员  
**核心需求：** 在"我的"页面直观展示个人参与数据，提升球员的参与感和成长感

---

## 1. 功能范围

在现有 `pages/my/index.tsx` 页面下方新增统计卡片区，不新增独立页面。展示以下 5 个指标：

| 指标 | 说明 |
|---|---|
| 出勤率 | 本赛季已参与活动数 / 队内已完成活动总数，百分比展示 |
| 本赛季场次 | 已参与的活动总次数（复用现有 `totalMatches` 字段） |
| 连续参与 | 最近连续出勤的场次数，遇到第一次缺席重置为 0 |
| 队内出勤排名 | 出勤率在全队的位次，格式"第 X / Y 名" |
| 月度趋势图 | 最近 6 个月每月参与场次，CSS 手写柱状图 |

**本期不做：** 里程碑徽章（10场/25场/50场），作为后续迭代。

---

## 2. 后端设计

### 接口

扩展现有接口，保持向后兼容：

```
GET /api/v1/users/me/stats?teamId={teamId}
```

### 响应结构（`MyStatsRes` 新增字段）

```java
// 现有字段保持不变
private int totalMatches;
private int wins;
private int draws;
private int losses;

// 新增字段
private double attendanceRate;        // 出勤率，如 0.85（85%）
private int currentStreak;            // 当前连续参与场次
private int teamAttendanceRank;       // 队内出勤排名（第几名）
private int teamMemberCount;          // 全队成员数（用于显示"第X/Y名"）
private List<MonthStat> monthlyStats; // 最近6个月数据

// MonthStat
private String month;  // "2026-05"
private int count;     // 当月参与场次
```

### 计算逻辑

**出勤率**
- 分子：`activity_registration` 中该用户在该队已参与（状态为已报名）且活动状态为 `CLOSED` 的记录数
- 分母：该队所有状态为 `CLOSED` 的活动总数
- 若分母为 0，返回 0.0

**连续参与**
- 取该队所有 `CLOSED` 活动，按活动时间倒序排列
- 逐一判断该用户是否有对应报名记录
- 遇到第一次缺席则停止计数，返回已累计的场次

**队内出勤排名**
- 对该队所有 `ACTIVE` 成员各自计算出勤率
- 按出勤率降序排名，取当前用户的位次
- 出勤率相同时，场次多者排前

**月度趋势**
- 取最近 6 个自然月（含当前月）
- 对每个月统计该用户在该队参与的已完成活动数
- 无参与的月份返回 count=0

## 3. 前端设计

### 布局（`pages/my/index.tsx`）

在现有内容下方追加统计区块：

```
┌─────────────────────────────────┐
│  出勤率 85%    连续参与 5场      │
│  本赛季 12场   队内排名 第3/12名 │
├─────────────────────────────────┤
│  近6个月参与趋势                 │
│  █ █   █ █ █ █                  │
│  12 8  0 10 9 12                │
│  12  1  2  3  4  5月            │
└─────────────────────────────────┘
```

### 实现细节

- 4 个数字指标用 2×2 网格排列
- 柱状图用 View + 内联样式手写，**不引入第三方图表库**（控制包体积）
- 柱子高度按当月场次与最大值的比例计算，最大高度固定 60px
- 缺席月份（count=0）柱子置灰，有参与的月份用主题色
- 数据加载中显示骨架屏占位（与现有页面风格一致）
- 复用现有 `useTeamStore` 获取 `teamId`，调用已有 `statsApi`
